These are prerequisites. None of them are granted by this repository, and this skill does not store key material.

Private repos `workflow-llc/app-ios` and `workflow-llc/android-app` were not readable from this workspace (GitHub returns 404 for the template token). Lane names below are detected from each checkout's `fastlane/Fastfile` at preview time. ## Wiring

1. Slack mention in a thread (`@HermesCR` on the code-review profile). The gateway session key includes platform, chat, and thread, and the turn runs with `task_id` set to that session id.
2. The profile loads this skill. The change loop builds and opens a PR. The store step runs `scripts/deploy_gate.py preview`.
3. The human replies with the same destination. `confirm` checks the preview token, credential presence, and lane. It does not upload.
4. An operator sets `MOBILE_DEPLOY_EXECUTE=1` only after the keys and the signing host exist. `confirm --execute` then runs the planned argv in the repo. The argv contains no key bytes.
5. iOS TestFlight or App Store: Fastlane lane when the repo has one, otherwise `lim upload` for TestFlight only. That command needs a Limrun or macOS signing host (`LIM_HOST_READY=1` or `darwin`).
6. Android: `./gradlew bundleRelease` produces the AAB. Play upload runs only a Fastfile lane named `internal` or `production`.

Artifact path: repo build output (Xcode archive via `lim` / Fastlane gym, or Gradle AAB), then the store tool. This template does not add a second uploader.

## Apple

Sources: [App Store Connect API](https://developer.apple.com/help/app-store-connect/get-started/app-store-connect-api/), [Upload builds](https://developer.apple.com/help/app-store-connect/manage-builds/upload-builds/), [TestFlight overview](https://developer.apple.com/help/app-store-connect/test-a-beta-version/testflight-overview/), [Roles](https://developer.apple.com/help/account/access/roles/).

Program and agreements:

- Apple Developer Program membership for the team that owns the app.
- Account Holder accepts the current license and any paid-app agreements before distribution.
- A bundle id registered for the app. TestFlight builds need that application identifier inside the provisioning profile.

API key, three separate values, used to sign a JWT:

- Issuer ID: identifies the App Store Connect team. It is not the key id and not the private key.
- Key ID: identifies one API key.
- Private key: the `.p8` downloaded once. Store it outside git at the path in `ASC_PRIVATE_KEY_PATH`, mode 600. This repo must never contain it.

Who can create keys:

- The Account Holder requests API access (Users and Access → Integrations → Request Access).
- Account Holder or Admin generates team keys and can revoke team or individual keys. Team keys apply to every app; app access cannot be limited on a team key.
- An individual key can be generated by Account Holder, Admin, App Manager, Customer Support, Developer, or Marketing, unless an Admin or Account Holder has turned off Generate Individual API Keys. The key has that user's permissions. Each user has one active individual key.

Upload versus submission:

- Upload builds: Account Holder, Admin, App Manager, or Developer. Admin is not required just to upload a build. Xcode, Transporter, altool, or the App Store Connect API (JWT from the same key) can upload.
- Create app records, submit for review, and manage App Store versions are narrower than upload. Developer can upload a build. Creating the app record and submitting for review sit with Account Holder, Admin, and App Manager (Developer needs a separate grant to create app records).
- TestFlight internal testers and external groups are managed in App Store Connect. The first external build can require beta review. A build is eligible for TestFlight only when its provisioning profile contains the application identifier.

Signing:

- Developer role needs Certificates, Identifiers & Profiles access, granted in Users and Access, to create development certificates, register App IDs, and download profiles. Account Holder and Admin have that access. Distribution certificates and distribution profiles are Account Holder or Admin.
- Cloud signing from this Linux gateway is not a local Mac codesign. `LIM_HOST_READY=1` means an operator has already connected `lim` to a host that can sign. This skill does not claim that host is connected.
- Automatic signing still needs the team membership, the bundle id, and a signing identity on that Mac or Limrun builder.

## Android

Sources: [Add users and permissions](https://support.google.com/googleplay/android-developer/answer/9844686), [Prepare and roll out a release](https://support.google.com/googleplay/android-developer/answer/9859348).

Play Console:

- A Play developer account. The account owner links the payments profile.
- The app's package name and Play App Signing. The first production or open-track publish fixes the signing key.
- Create a release on internal, closed, open, or production. Internal testing is up to 100 testers. Creating a release requires Release apps to testing tracks. Production rollout is a separate Start rollout and requires Release to production, exclude devices, and use Play App Signing.

Service account:

- Create the account in Google Cloud and download its JSON key once. Point `PLAY_SERVICE_ACCOUNT_JSON` at that file, mode 600, outside git.
- Invite that service-account email as a Play Console user (Users and permissions). Grant app-scoped permissions, not account-admin, unless an admin decides otherwise.
- Internal or other testing upload: View app information (read-only) and Release apps to testing tracks.
- Production: those testing permissions are not enough. Also grant Release to production, exclude devices, and use Play App Signing. Keep that permission off the key used for internal uploads when the two actions are meant to stay separate.
- This repository does not hold that JSON and does not treat the permission as already granted.

Gradle and Fastlane:

- `./gradlew bundleRelease` is the artifact command when `gradlew` is in the checkout.
- Play upload runs only if `fastlane/Fastfile` defines `lane :internal` or `lane :production`. A lane named only `supply` is ignored so the track is not guessed.
